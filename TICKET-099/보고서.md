TCP는 경계가 없는 스트림이라 `Receive(buf, 0, size)` 는 **지금 와 있는 만큼만** 돌려준다. L63은 반환값(실제로 읽은 바이트 수)을 버리고 반복하지 않으므로, 본문이 반만 도착한 순간 나머지가 0으로 찬 버퍼를 그대로 JSON으로 파싱한다 → 예외. 뒤에 도착한 나머지 반쪽은 다음 패킷의 헤더로 잘못 읽힌다. 헤더(L51)도 4바이트를 다 받았는지 확인하지 않는다.

**수업 근거** — 3주차 9쪽 "TCP는 스트림 … 반대로 잘려서 올 수도 있습니다", 3주차 10쪽 "먼저 4바이트를 읽는다 → 그 다음 **정확히** 30바이트를 읽는다". 5주차 실습 코드 PacketHelper의 `ReceiveExactAsync` 는 "100바이트를 요청해도 30바이트만 올 수 있어요. 그래서 다 받을 때까지 반복합니다"라며 반복해서 읽는데, 납품본은 이 반복을 없앴다.

**고친 코드**
```csharp
// before (L51, L63)
int n = await Task.Run(() => socket.Receive(header, 0, 4, SocketFlags.None));
...
await Task.Run(() => socket.Receive(body, 0, bodyLength, SocketFlags.None));

// after — 요청한 바이트를 다 받을 때까지 반복
if (!await ReadExactAsync(socket, header, 4)) return null;
...
if (!await ReadExactAsync(socket, body, bodyLength)) return null;

private static async Task<bool> ReadExactAsync(Socket socket, byte[] buffer, int size)
{
    int read = 0;
    while (read < size)
    {
        int n = await Task.Run(() => socket.Receive(buffer, read, size - read, SocketFlags.None));
        if (n == 0) return false;   // 상대가 연결을 닫음
        read += n;
    }
    return true;
}
```
(이 단계에서는 블로킹 `Receive` 를 일부러 남겨 둔다. A2에서 따로 고쳐 부하 개선 효과를 분리한다.)

- before: `측정결과_〔학번〕.csv` 〔측정시각 〔 〕 행들〕, `증거/B1_before_load_〔 〕.png`
- after: 같은 CSV 〔측정시각 〔 〕 행들〕, `증거/B3_after_load_〔 〕.png` (A1만 고친 측정 ②는 `B2_mid_load_〔 〕.png`)

**원인** — `OutsourcedServer/PacketHelper.cs` L51, L63 (원본)
`Task.Run(() => socket.Receive(...))` 는 비동기처럼 보이지만, 스레드풀 스레드 하나가 **데이터가 올 때까지 Receive 안에서 잠들어** 있다. 로그인한 접속자는 다음 패킷을 기다리는 동안 계속 스레드 하나를 붙잡으므로 접속자 수 = 묶인 스레드 수. 스레드풀은 처음에 코어 수(〔N〕)만큼만 스레드를 두고 그 뒤로는 천천히 늘리기 때문에, 그 수를 넘는 접속자의 처리(WELCOME 전송, Accept 계속하기)가 줄을 서서 기다린다. 자세한 수치 분석은 Part B.

**수업 근거** — 4주차 16쪽 "흔한 실수: 네트워크 대기를 Task.Run 으로 감싸는 것 → 대기 중에는 CPU를 안 쓰는데, 쓰레드만 하나 더 잡아먹습니다 → 오히려 손해입니다" (예제 B 5번 메뉴도 같은 내용). 납품본 PacketHelper.cs L50 주석 "Receive는 블로킹 함수라서 Task.Run으로 감싸 비동기화했습니다"가 바로 그 실수다. 4주차 8쪽 C10K "네트워크 대기 중에는 CPU가 할 일이 없습니다", 10쪽 "Thread.Sleep = 쓰레드를 붙잡음 / await = 반납함". 5주차 실습 코드는 `await socket.ReceiveAsync(...)` 를 쓴다.

**고친 코드**
```csharp
// before (A1 수정 후의 ReadExactAsync 안)
int n = await Task.Run(() => socket.Receive(buffer, read, size - read, SocketFlags.None));

// after — 기다리는 동안 스레드를 돌려주는 진짜 비동기 수신
int n = await socket.ReceiveAsync(
    new ArraySegment<byte>(buffer, read, size - read), SocketFlags.None);
```

### A4. 위치 패킷 뒤에 이전 패킷 찌꺼기가 붙어 좌표가 틀어진다 ⚠검증 전
